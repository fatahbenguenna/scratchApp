## Story

**En tant qu'**utilisateur,
**je veux** que chaque son importé soit copié et vérifié dans l'app,
**afin de** le recharger plus tard même si l'original disparaît.

## Critères d'acceptation

1. **Chaîne d'import (5.3, SF-02, RM-47, RM-48).** `importFile(at:)` : copie en flux dans un fichier temporaire du même volume (`Application Support/ScratchApp/Imports/<UUID>.<ext>`) avec calcul de l'empreinte SHA-256 pendant la copie ; validation par la sonde du protocole de décodage (décodable, non protégé, durée de 50 ms à 10 min) ; déplacement atomique dans `Documents/Banque de sons/` ; puis écriture atomique de l'index.
2. **Source intacte (SF-02 ; 6.1 « Un import ne modifie pas le fichier source »).** Le fichier source n'est jamais modifié (contenu et date de modification identiques) ; aucun signet ni chemin externe n'est conservé dans l'index.
3. **Erreurs typées, transaction complète (RM-48 ; 6.1).** Espace insuffisant (contrôle préalable par un fournisseur d'espace injectable, puis erreur d'écriture `ENOSPC`) → `insufficientStorage` ; format non pris en charge, contenu protégé, fichier corrompu ou vide, trop long, trop court → erreur de la sonde propagée ; autre échec d'écriture → `writeFailed(reason:)`. Dans tous les cas, aucune copie n'est conservée (temporaire supprimé), aucune entrée n'est ajoutée et l'index est inchangé.
4. **Dédoublonnage (critère P1 porté par cette story, D-01, D-19 ; SF-75 ; 6.1 « Importer un contenu déjà présent dans la bibliothèque »).** Un contenu de même empreinte qu'une entrée existante (dont la copie est valide) ne crée pas de seconde copie : `.existing(entry)` est renvoyé et le temporaire supprimé.
5. **Nommage des copies (SF-02, SF-60, RM-43, D-12 ; 6.13 « Importer deux fichiers portant le même nom »).** La copie garde le nom d'origine ; en cas de collision, un suffixe `_2`, `_3`… est ajouté avant l'extension (`voix_funk_2.wav`), sans jamais écraser une copie ; le titre de l'entrée est le nom de la copie, ce qui distingue deux homonymes.
6. **Rechargement local (SF-20 ; 6.1 « Recharger un son déjà importé sans accéder à Drive », `@P1`).** `url(for:)` fournit l'URL de la copie vérifiée (3.1) ; le rechargement ne dépend jamais de la source, même supprimée.
7. **Échec sans effet (RM-48).** Un échec d'import n'a aucun effet sur l'index existant ni sur les copies existantes ; les temporaires orphelins de `Imports/` sont purgés au premier accès du magasin.
8. **Concurrence.** Deux imports simultanés (un par platine) sont sérialisés par l'acteur sans perte ni doublon : deux imports concurrents du même contenu donnent une seule copie (`.added` puis `.existing`).
9. **Tests Linux** avec un décodeur factice (WAV PCM générés par le test), un fournisseur d'espace simulé et des dossiers temporaires.

### Scénarios de vérification

```gherkin
Feature: Import (Linux, décodeur factice)

  Scenario: Importer deux fichiers portant le même nom (D-12)
    Given "voix_funk.wav" est dans la bibliothèque
    When j'importe un autre "voix_funk.wav" au contenu différent
    Then sa copie est "Banque de sons/voix_funk_2.wav"
    And la copie "voix_funk.wav" est inchangée
    And les deux entrées ont pour titres "voix_funk.wav" et "voix_funk_2.wav"

  Scenario: Échec de copie faute d'espace (6.1)
    Given le fournisseur d'espace annonce moins que la taille du fichier
    When j'importe "boucle.wav"
    Then l'erreur insufficientStorage est levée
    And "Banque de sons" et "Imports" ne contiennent aucun nouveau fichier
    And library.json est inchangé octet pour octet

  Scenario: Contenu déjà présent (SF-75, @P1)
    Given "boucle.wav" a été importé
    When j'importe "copie de boucle.wav" au contenu identique
    Then le résultat est .existing avec l'entrée de "boucle.wav"
    And aucune seconde copie n'existe
```

public protocol LibraryStoring: Sendable {
    var entries: [LibraryEntry] { get async }
    func reconcile() async -> [LibraryEntry]                    // 3.1 (D-11)
    func importFile(at url: URL) async throws -> ImportResult   // cette story
    func delete(id: UUID) async throws
    func url(for id: UUID) async throws -> URL

public enum ImportResult: Equatable, Sendable {

### Persistance (architecture §8)

| Contenu | Emplacement | Écriture |
|---|---|---|
| Temporaire d'import | `Application Support/ScratchApp/Imports/<UUID>.<ext>` | supprimé en fin d'import ; purgé au lancement |
| Copie | `Documents/Banque de sons/<nom d'origine>` ou `<nom>_<n>.<ext>` | `FileManager.moveItem` (atomique sur le même volume) |
| Index | `Application Support/ScratchApp/library.json` | `Data.write(options: .atomic)` **après** le déplacement |

Garantie transactionnelle (§7.2) : sur toute erreur, temporaire supprimé, index inchangé, platine non modifiée (l'`AppModel` n'envoie rien).

### Accès au fichier source

- L'URL à portée de sécurité (`startAccessingSecurityScopedResource`) est ouverte et refermée **par l'`AppModel`** (6.1) autour de l'appel `importFile(at:)` : `LibraryStore` reste compilable sous Linux.
- Lecture coordonnée pour iCloud Drive (`NSFileCoordinator`, Apple seulement) : facultative ici sous `#if canImport(Darwin)` ; sinon lecture directe. Un fichier non téléchargé ou illisible lève `writeFailed(reason:)` (l'`AppModel` affiche « Échec de l'import » ; un cas « Fichier inaccessible » distinct de l'UX §8.3 demanderait un nouveau cas de `LibraryError` : point ouvert pour Winston, non bloquant).

### Pièges connus

- **Réentrance d'acteur (CA 8).** `await decoder.probe(...)` suspend l'acteur : un second import peut s'exécuter entre-temps. Re-vérifier l'empreinte et le nom final **après** la sonde (ou réserver l'empreinte et le nom dans un ensemble « en cours ») ; sinon deux imports identiques créent deux copies, ou deux homonymes visent le même nom.
- **Même volume.** `Application Support` et `Documents` sont dans le conteneur de l'app : `moveItem` est atomique. En test, `LibraryLocations` pointe deux sous-dossiers du même dossier temporaire.
- **Nom d'origine** : conserver le nom tel quel (accents, espaces) ; refuser `/` et les noms commençant par `.` ; extension conservée en minuscules ou telle quelle (documenter).
- **Dédoublonnage et copie disparue** : si l'entrée de même empreinte a perdu sa copie, la réconciliation (3.1) la retire ; l'import redevient un ajout.
- **Erreur d'écriture simulée** : `ENOSPC` est difficile à provoquer sous Linux ; prévoir un point d'injection interne pour l'écriture du temporaire (protocole interne, `@testable`).
- **Titre** : `LibraryEntry.title` = nom de la copie, suffixe compris (D-12) ; `decode(url:title:)` reçoit ce titre en 6.1.
- **Langue (D-42)** : identifiants en anglais, `///` en français, `//` en anglais.
