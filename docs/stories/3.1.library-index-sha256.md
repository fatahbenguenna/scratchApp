## Story

**En tant qu'**utilisateur,
**je veux** que les sons copiés dans l'app soient indexés de façon durable,
**afin de** les retrouver intacts à chaque lancement, sans connexion.

## Critères d'acceptation

1. **Entrées (RM-58, SF-74, D-36, D-41).** `LibraryStore` implémente la partie index du protocole `LibraryStoring` : `entries`, `reconcile()`, `delete(id:)`, `url(for:)`. Chaque entrée porte un UUID stable, une empreinte SHA-256, le nom et la taille de sa copie, le titre, la durée, la date d'import (seule date en V1) et l'origine (`.imported` ou `.demo`, affichées « Import » et « Intégré » par l'écran 3.5) (`LibraryEntry`, contrat 0.2). `entries` renvoie le son de démonstration en tête, puis les imports du plus récent au plus ancien.
2. **Index atomique et versionné (5.3).** L'index `Application Support/ScratchApp/library.json` a la forme `{"version": 1, "entries": [LibraryEntry]}`, dates ISO 8601, et s'écrit de façon atomique (fichier temporaire puis remplacement). La démo n'y est jamais écrite.
3. **Index illisible (NFR12).** Un index illisible ou d'une version inconnue est mis de côté (`library.json.corrupt`, sans écraser un précédent) ; la bibliothèque repart vide, sans plantage.
4. **Réconciliation et contrat (RM-48, D-11, réserve R4).** Le contrat `LibraryStoring` reçoit une opération `reconcile() async -> [LibraryEntry]` (changement de contrat porté par cette story, avec l'accord de Winston) : elle retire de l'index (réécrit de façon atomique) toute entrée dont la copie est absente ou de taille différente de `fileSize`, et renvoie les entrées retirées par cet appel. L'`AppModel` l'appelle au lancement (bandeau, 6.1) ; `url(for:)` applique la même vérification à l'entrée demandée : copie absente ou modifiée → entrée retirée et `LibraryError.notFound` (alerte « Son introuvable », 6.1). Les fichiers de `Banque de sons` absents de l'index sont ignorés en V1 (6.13 « Copie supprimée en dehors de l'application », « Charger un son dont la copie a disparu »).
5. **SHA-256 portable (RM-58, ADR-09).** `ContentHasher.sha256Hex(of:)` et `sha256Hex(ofFileAt:)` calculent un SHA-256 en Swift pur, **sans CryptoKit**, en hexadécimal minuscule, le fichier étant lu en flux par blocs de 1 Mio ; vecteurs officiels vérifiés (chaîne vide, « abc », message de 448 bits, un million de « a »), résultats identiques sous Linux et macOS.
6. **Suppression (RM-49 ; 6.13 « Supprimer un son non chargé »).** `delete(id:)` supprime la copie de `Documents/Banque de sons/`, puis l'entrée ; la démo lève `demoCannotBeDeleted`, une entrée inconnue `notFound` ; aucun fichier hors de `Banque de sons` n'est touché, même si l'index contient un nom forgé (`../`, chemin absolu).
7. **Identité stable (RM-58).** L'UUID d'une entrée ne change jamais : il survit à la relecture de l'index et à la réconciliation des autres entrées.
8. **Persistance (6.13 « Retrouver la bibliothèque après relancement », SF-20).** Une nouvelle instance de `LibraryStore` sur les mêmes emplacements retrouve les mêmes entrées, hors ligne.
9. **Tests Linux** dans des dossiers temporaires uniques (`LibraryLocations` injecté) ; `importFile` reste hors périmètre (story 3.2) et continue de lever une erreur.

### Contrats à implémenter (Contracts/ : seul `LibraryStoring` change, voir « Changement de contrat »)

```swift
public struct LibraryEntry: Codable, Equatable, Hashable, Identifiable, Sendable {
    public enum Origin: String, Codable, Sendable, CaseIterable { case imported, demo, microphone, mix }
    public let id: UUID                  // stable (RM-58)
    public var contentHash: String       // SHA-256 hexadécimal minuscule ; "" pour la démo
    public var fileName: String          // nom de la copie dans « Banque de sons » ; "" pour la démo
    public var fileSize: Int64           // octets ; copie de taille différente → entrée écartée (IC-10)
    public var title: String
    public var duration: Double
    public var importedAt: Date
    public var origin: Origin
    public var isDeletable: Bool { get }              // false pour la démo
    public static let demoID: UUID                    // 5C2A7C40-DE30-4D3A-9B1E-000000000001
    public static func demo(title: String, duration: Double) -> LibraryEntry
}

public protocol LibraryStoring: Sendable {
    var entries: [LibraryEntry] { get async }         // démo en tête, puis imports du plus récent au plus ancien
    // + func reconcile() async -> [LibraryEntry]     // ajouté par cette story (D-11), voir plus bas
    func importFile(at url: URL) async throws -> ImportResult   // story 3.2
    func delete(id: UUID) async throws                // copie seule (RM-49) ; démo → demoCannotBeDeleted
    func url(for id: UUID) async throws -> URL        // copie vérifiée ; absente → entrée écartée, notFound
}

public enum LibraryError: Error, Equatable, Sendable {
    case insufficientStorage, unsupportedFormat, protectedContent
    case tooLong(duration: Double), tooShort(duration: Double)
    case corrupted, writeFailed(reason: String), notFound, demoCannotBeDeleted
    public var userMessage: String { get }            // français
}
```

### Pièges connus

- **Linux.** Pas de CryptoKit, pas de `CommonCrypto`, pas de `NSFileCoordinator`. `FileHandle.read(upToCount:)` et `Data.write(options: .atomic)` existent sous swift-corelibs-foundation. Vérifier `scripts/linux-test.sh` avant la PR.
- **Rembourrage SHA-256** : cas limites à 55, 56, 63, 64 et 119 octets ; et un fichier de 1 Mio ± 1 octet pour la frontière de bloc de lecture.
- **Performance** : arithmétique `&+`, rotations sur `UInt32`, tableau de 64 mots réutilisé ; les tests tournent en débogage : garder des tailles modestes (le million de « a » reste rapide).
- **Un son déjà chargé** reste jouable depuis la mémoire quand sa copie disparaît (D-11) : la bibliothèque ne commande jamais le moteur.
- **Réentrance d'acteur** : ne pas `await` entre la lecture et l'écriture de l'index (3.2 ajoutera des `await` vers le décodeur : prévoir un index en mémoire seul maître, écrit d'un bloc).
- **Chemins forgés** : construire l'URL d'une copie par `soundBankDirectory.appendingPathComponent(fileName)` et refuser tout `fileName` vide, contenant `/`, `..` ou commençant par `.`.
- **Dates** : `JSONEncoder.DateEncodingStrategy.iso8601` perd les fractions de seconde ; comparer les dates arrondies à la seconde dans les tests, ou utiliser un format ISO 8601 avec fractions des deux côtés.
- **Tri** : à date égale, ordre stable (par exemple par titre puis UUID) pour des tests déterministes.
