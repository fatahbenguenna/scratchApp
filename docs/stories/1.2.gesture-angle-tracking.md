## Story

**En tant que** DJ,
**je veux** que la rotation de mon doigt, de ma souris ou de mon trackpad soit convertie fidèlement en angle de disque,
**afin que** le scratch suive exactement mon geste, sans saut.

## Critères d'acceptation

1. **Angle déplié, gain 1:1 (5.1 §5, RM-04).** L'angle du contact est mesuré par `atan2` autour du centre du disque, dans le repère d'écran à axe y vers le bas (sens horaire positif), et déplié : un geste continu de +3 tours donne +6π rad à 10⁻⁶ près, sans saut à ±π ; un tour de doigt = un tour de disque.
2. **Saisie au départ seulement (RM-60).** Un contact ne saisit un disque que s'il commence dans sa zone de saisie (rayon `min(R + 6, P / 2)`, UX §5.1) ; un contact qui y entre en glissant ne le saisit pas (Gherkin 6.3 « Geste commencé hors du disque »). Un contact qui sort du disque en cours de geste garde la saisie.
3. **Un seul propriétaire par disque (RM-60, SF-19).** Le premier contact devient le propriétaire ; tout autre contact commencé sur ce disque est ignoré jusqu'au relâchement du premier (6.3 « Deuxième doigt sur le même disque »). Deux disques sont suivis indépendamment (6.8 « Scratcher les deux disques en même temps sur iPad »).
4. **Annulation = relâchement (RM-60).** Une annulation par le système produit un relâchement ; aucun état « tenu » ne subsiste (6.3 « Toucher annulé par le système »).
5. **Zone centrale (RM-61).** Rayon < 12 % de R : le contact retient le disque sans le faire tourner (angle figé) ; en sortie de zone, le suivi reprend depuis l'angle courant, sans saut. Un contact qui entre dans la zone en cours de geste gèle l'angle de la même façon (6.3 « Doigt posé au centre du disque »).
6. **Touches regroupées et prédites (SF-78, D-16).** Les échantillons de contact sont horodatés et acceptés par lots, dans l'ordre ; chaque échantillon réel produit un `touchMoved(predicted: false)`. Un échantillon prédit produit un `touchMoved(predicted: true)` calculé **sans modifier l'état de dépliement** : l'échantillon réel suivant est calculé depuis le dernier échantillon réel, sans erreur cumulée. Côté moteur, les touches prédites ne servent qu'à combler l'attente du rejeu entre deux lots, jamais au-delà du dernier échantillon réel d'une durée supérieure à un intervalle de livraison, et sans aucun dépassement dans le mauvais sens aux inversions (SF-77) ; leur emploi est décidé et calibré ici, mesure à l'appui (profils d'appareils de `FingerTrajectoryTests`). Si le calibrage ne montre aucun gain de retard sans dépassement, la décision documentée est de les ignorer.
7. **Défilement trackpad (SF-79, D-24, UX §6.3).** Un défilement commencé (phase « began ») au-dessus de la zone de saisie saisit le disque ; commencé ailleurs, il ne le saisit pas. Chaque delta donne `Δθ = (rx·dy − ry·dx) / (‖r‖ × max(‖r‖, 0,5 R))` (sens horaire positif, `r` = centre → pointeur, `r` pris en haut du disque à 0,5 R dans la zone centrale). L'inertie (`momentum`) est ignorée. La molette sans phases tourne de 15° par cran. Le relâchement est émis 80 ms après le dernier événement, mesurés sur une horloge injectée, avec l'horodatage `dernier événement + 0,080 s` (6.14 « Scratcher au trackpad »).
8. **Géométrie variable (6.14).** Un changement de centre ou de rayon pendant un geste (redimensionnement, rotation) ne produit aucun saut d'angle : l'angle est recalé sur le dernier point connu avec la nouvelle géométrie (6.14 « Redimensionner la fenêtre pendant un scratch »).
9. **Sortie en commandes, logique pure.** La sortie est la suite d'`EngineCommand` du contrat 0.2 pour une platine donnée : `touchBegan(deck, angle:, time:)`, `touchMoved(deck, angle:, time:, predicted:)`, `touchEnded(deck, time:)`. Aucune dépendance à UIKit, AppKit ni SwiftUI ; tests Linux.

### API proposée (Léa la fixe dans la PR ; elle est consommée par sa propre story 4.3)

```swift
/// Un échantillon de contact, dans le repère de la vue du disque (points, y vers le bas).
public struct ContactSample: Equatable, Sendable {
    public var x: Double, y: Double
    public var time: Double              // horloge monotone de l'appelant (UITouch/NSEvent.timestamp)
    public var isPredicted: Bool
}

/// Session de geste d'un disque : contact propriétaire, angles dépliés, commandes moteur.
public struct DiscGestureSession: Sendable {
    public let deck: DeckID
    public private(set) var ownerID: Int?            // identifiant de contact (ObjectIdentifier(UITouch).hashValue…)
    public init(deck: DeckID, centerX: Double, centerY: Double, vinylRadius: Double, grabRadius: Double)
    public mutating func updateGeometry(centerX: Double, centerY: Double, vinylRadius: Double, grabRadius: Double)
    /// Renvoie touchBegan si le contact devient propriétaire, sinon rien.
    public mutating func began(contact id: Int, at sample: ContactSample) -> EngineCommand?
    /// Échantillons regroupés puis prédits, dans l'ordre ; ignorés si `id` n'est pas le propriétaire.
    public mutating func moved(contact id: Int, samples: [ContactSample]) -> [EngineCommand]
    public mutating func ended(contact id: Int, time: Double) -> EngineCommand?   // fin ou annulation
    public mutating func cancelAll(time: Double) -> EngineCommand?
}

/// Défilement trackpad / molette → rotation ; relâchement 80 ms après le dernier événement.
public struct ScrollGestureMapper: Sendable {
    public enum Phase: Sendable { case began, changed, ended, momentum, none }  // none = molette classique
    public init(deck: DeckID, centerX: Double, centerY: Double, vinylRadius: Double, grabRadius: Double,
                releaseDelay: Double = TurntableConstants.trackpadReleaseDelay)
    public mutating func scroll(x: Double, y: Double, deltaX: Double, deltaY: Double,
                                phase: Phase, time: Double) -> [EngineCommand]
    public var releaseDeadline: Double? { get }       // dernier événement + 0,080 s
    public mutating func poll(now: Double) -> EngineCommand?                  // touchEnded à l'échéance
}
```

Les tableaux renvoyés sont acceptables : ce code s'exécute sur le fil principal, jamais sur le fil audio. L'appelant (4.3) envoie chaque commande au moteur dans le cycle d'événements qui la reçoit (`DeckViewModel.touchBegan/Moved/Ended` ou `engine.send`).

### Contrat moteur utilisé (ne pas modifier)

```swift
public enum EngineCommand {
    case touchBegan(DeckID, angle: Double, time: Double)                          // ignoré si déjà tenu (RM-60)
    case touchMoved(DeckID, angle: Double, time: Double, predicted: Bool = false)  // chaque touche regroupée
    case touchEnded(DeckID, time: Double)                                         // relâchement ou annulation
    // …
}
```

- **Angle** : radians, cumulé, positif dans le sens horaire, 0 = midi ; repère d'écran à axe y vers le bas (`NSView` avec `isFlipped == true` côté Mac). Dans ce repère, `atan2(dy, dx)` croît dans le sens horaire ; l'origine de l'angle (midi ou 3 h) n'a pas d'importance pour le moteur, qui travaille en relatif.
- **Prise relative (ADR-08)** : le moteur mémorise `gripOffset = θd − θf` à `touchBegan`. Le traqueur n'a **pas** besoin de connaître l'angle du disque : il fournit l'angle propre du doigt. La saisie d'un disque en rotation est donc sans saut côté moteur.
- **Temps** : horloge monotone de l'appelant, la même pour tout le geste ; temps strictement croissants (le moteur ignore un `touchMoved` dont le temps n'est pas supérieur au précédent).

### Pièges connus

- **Dépliement** : calculer `Δ = atan2(y, x) − dernierBrut`, le ramener dans ]−π ; π], l'ajouter à l'angle cumulé. Ne jamais dériver l'angle cumulé directement d'`atan2`.
- **Zone morte** : pendant le gel, continuer à mettre à jour `dernierBrut` avec le point courant ; à la sortie, reprendre le dépliement depuis ce point. Sinon le premier mouvement hors zone ajoute tout l'angle parcouru dans la zone (saut).
- **Touches prédites** : ne mettent à jour ni `dernierBrut` ni l'angle cumulé ; elles sont recalculées à chaque lot (UIKit renvoie de nouvelles prédictions à chaque `touchesMoved`). Côté moteur, une prédiction ne doit jamais faire avancer la tête de rejeu au-delà de ce que confirmera l'échantillon réel : au moment d'une inversion, la prédiction va dans le mauvais sens ; borner l'extrapolation et la corriger par un lissage, sinon le baby scratch « bave » (SF-77).
- **Géométrie** : recaler `dernierBrut` sur le **dernier point connu** exprimé dans la nouvelle géométrie ; l'angle cumulé ne change pas.
- **Défilement naturel** : la correction du sens (« défilement naturel » du système) est appliquée par la vue AppKit (4.3) avant l'appel ; les deltas reçus ici sont des déplacements de doigts dans le repère de la vue (y vers le bas).
- **Relâchement du trackpad** : émettre `touchEnded` avec `time = dernierÉvénement + 0,080`, pas avec l'heure de `poll` : le moteur rejoue le geste, le disque reste immobile 80 ms puis il est relâché. Une phase `ended` explicite ne relâche pas plus tôt (règle des 80 ms).
- **Identifiants de contact** : ne pas garder de référence à `UITouch` (type UIKit, absent sous Linux) ; utiliser un entier fourni par l'appelant.
