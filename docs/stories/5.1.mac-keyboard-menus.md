## Story

**En tant que** DJ sur Mac,
**je veux** piloter transport, CUE, pitch, coupures et crossfader au clavier et par les menus,
**afin de** scratcher à la souris d'une main et de couper le son de l'autre.

## Critères d'acceptation

1. **Raccourcis par position physique (3.5, D-08, D-09 ; 6.14 « Piloter le transport au clavier », « Déplacer le crossfader au clavier », « Raccourcis sur un clavier AZERTY » ; 6.10 « Butées au clavier avec le hamster (Mac) »).** `Q`/`P` START/STOP ; `A`/`S` et `L`/`K` SET CUE/CUE ; `F`/`J` coupure momentanée ; `Z`/`X` et `,`/`.` pitch −/+0,1 % ; `←`/`→` crossfader par pas de 5 % vers la gauche ou la droite ; `⇧←`/`⇧↓`/`⇧→` butée gauche, centre, butée droite **physiques**, quel que soit le hamster. Les touches sont lues par code de touche (disposition QWERTY de référence), sur AZERTY comme sur QWERTY.
2. **Coupure momentanée (3.5, SF-79, D-06 ; 6.14 « Couper le son au clavier pendant un scratch à la souris »).** La voie est ouverte tant que la touche est enfoncée et refermée au relâchement, y compris pendant un scratch à la souris, sans l'interrompre ; `F` et `J` peuvent être maintenues ensemble ; si la fenêtre perd le focus, si l'app passe en arrière-plan ou si une feuille s'ouvre pendant le maintien, la voie se referme.
3. **Répétition (D-25).** La répétition automatique ne redéclenche ni START/STOP, ni SET CUE, ni CUE, ni les coupures, ni les butées ; elle est acceptée pour le pitch et pour `←`/`→`.
4. **Raccourcis inactifs (6.14 « Raccourcis inactifs pendant la saisie de texte », D-07).** Les touches simples et les flèches sont inactives quand un champ de texte a le focus, qu'une feuille, une alerte, un popover ou le panneau d'ouverture est au premier plan, ou que la fenêtre principale n'est pas active ; elles n'agissent que sans ⌘, ⌥ ni ⌃ (⇧ seulement avec les flèches), verrouillage majuscule ignoré. Une commande réglable qui a le focus clavier reçoit les flèches (règle complétée en 5.3).
5. **Menus (SF-79, D-34 ; 6.1 « Importer depuis le Finder sur Mac »).** Fichier : « Importer sur la platine A… » ⌘O, « Importer sur la platine B… » ⇧⌘O, « Bibliothèque » ⌘L, « Afficher la bibliothèque dans le Finder », « Nouvelle fenêtre » retiré ; Platine : sections A et B (START/STOP, 33⅓ tours, 45 tours, SET CUE, CUE, Pitch −0,1 %, Pitch +0,1 %, Pitch à 0 %) ; Table (crossfader à gauche, à droite, butées et centre, Hamster coché) ; Aide (« Raccourcis clavier de ScratchApp »). Les éléments à touche simple sont désactivés pendant une saisie ou un dialogue ; `F` et `J` ne figurent que dans l'aide. Les commandes sont livrées sous forme d'un type `Commands` que 6.2 attache à la scène.
6. **Carte unique et aide (D-08).** Une carte unique des raccourcis alimente le clavier, les menus et la vue d'aide « Raccourcis clavier » (560 × 440, groupes Platine A, Platine B, Global, pied de l'UX §5.22), intégrée aux réglages en 3.4 ; l'aide et les menus affichent le caractère réel de la disposition de clavier active (« A » pour START/STOP A sur AZERTY).
7. **Tests.** Tests unitaires de la carte code de touche → action, de l'appui et du relâchement, de la répétition, des modificateurs et de l'état « inactif ».

## Dev Notes

### API utilisées

```swift
// DeckViewModel (4.1) et MixerViewModel (4.2), Léa
deck.toggleMotor(); deck.setCue(); deck.recallCue(); deck.nudgePitch(steps: ±1); deck.resetPitch()
deck.setSpeed(.rpm33 / .rpm45)
mixer.nudgeCrossfader(steps: ±1)            // pas de 5 % (TurntableConstants.keyboardCrossfaderStep)
mixer.setCrossfader(0 / 0.5 / 1); mixer.setHamster(_:); mixer.setMomentaryCut(.a/.b, open:)
// DeckIntents (4.1), implémenté par l'AppModel (6.1, Hugo)
intents.importFile(on: .a / .b); intents.openLibrary(); intents.revealLibraryInFinder(); intents.openSettings()
```

**Butées physiques (D-09).** Le crossfader du contrat vaut 0 = butée A, 1 = butée B **avant** hamster ; à l'écran, la butée gauche est toujours à gauche. Sans hamster, gauche = 0 ; avec hamster, la position du contrat est inversée par le moteur (`x → 1 − x`) : `⇧←` doit donc rendre audible seulement la voie B (6.10 « Butées au clavier avec le hamster ») ; vérifier la convention exacte avec `CrossfaderCurve` et le moteur (1.4) et l'écrire dans un test.

### Codes de touche (disposition QWERTY de référence, `kVK_ANSI_*`)

| Touche | Code | Action |
|---|---|---|
| Q / P | 12 / 35 | START/STOP A / B (répétition ignorée) |
| A / S | 0 / 1 | SET CUE / CUE A |
| L / K | 37 / 40 | SET CUE / CUE B |
| F / J | 3 / 38 | coupure momentanée A / B (appui ouvre, relâchement ferme) |
| Z / X | 6 / 7 | pitch A −/+0,1 % (répétition acceptée) |
| , / . | 43 / 47 | pitch B −/+0,1 % (répétition acceptée) |
| ← / → | 123 / 124 | crossfader −/+5 % (répétition acceptée) |
| ⇧← / ⇧↓ / ⇧→ | 123 / 125 / 124 + ⇧ | butée gauche / centre / butée droite (répétition ignorée) |
| ⌘O / ⇧⌘O / ⌘L | menus | importer sur A / sur B, bibliothèque |

### Pièges connus

- **Double déclenchement (UX §6.4, Q12).** Un élément de menu à touche simple (`.keyboardShortcut("q", modifiers: [])`) et le moniteur clavier peuvent réagir tous les deux à la même frappe : faire passer les touches de performance par le seul moniteur (qui consomme l'événement) et laisser les menus déclencher la même action par le clic ; ou l'inverse, mais un seul chemin par frappe. Vérifier qu'un élément de menu désactivé laisse passer la frappe au champ de texte.
- **Relâchement** : les menus ne connaissent pas le relâchement : `F`/`J` passent obligatoirement par le moniteur (`keyUp`).
- **Champ de texte** : tester `NSApp.keyWindow?.firstResponder is NSText` (éditeur de champ) ; fenêtre principale = fenêtre clé sans feuille attachée (`attachedSheet == nil`) ni fenêtre modale.
- **Position physique** : comparer `event.keyCode`, jamais `charactersIgnoringModifiers` (D-08).
- **Raccourcis iPad** : hors V1 (D-32), même avec un clavier physique.
- **Avant 6.2**, les menus ne sont pas attachés : vérifier par tests unitaires et aperçus ; le moniteur clavier fonctionne dès cette story (installé par la vue racine).
- **Langue (D-42)** : identifiants en anglais, `///` en français, `//` en anglais.
